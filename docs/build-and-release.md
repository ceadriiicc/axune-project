# Building Axune Mobile for a device

## Install layout (important)

`apps/mobile` keeps its **own** `node_modules` on purpose. npm workspace hoisting splits Expo's
dependency tree — `expo-router` stays nested while `babel-preset-expo` and `@expo/cli` hoist to
the root — and bundling then fails with:

```
Invalid call at line 2: process.env.EXPO_ROUTER_APP_ROOT
```

The shared packages are linked with `file:` dependencies instead, and `metro.config.js` watches
`../../packages` so their TypeScript sources are transformed. Do not add `apps/mobile` to a
workspaces array.

Install and run:

```bash
npm --prefix apps/mobile install
npm run mobile
```

## Pre-flight before every build

Run this first — it catches config and dependency problems in seconds instead of 20 minutes into
a cloud build:

```bash
cd apps/mobile && npx expo-doctor
```

It must report all checks passing. It previously caught a missing `expo-constants` peer
dependency, which crashes standalone builds (Expo Go bundles it, so a device build is the first
place you would see it).

Icons are generated from code, not hand-edited:

```bash
powershell -NoProfile -File apps/mobile/scripts/generate-icons.ps1
```

`icon.png` is written as 24-bit RGB with **no alpha channel** on purpose — Apple rejects App
Store icons that carry one.

## TestFlight (requires the Apple Developer Program)

These steps need Apple and Expo credentials, so **run them yourself in a terminal** — the login
steps are interactive (Apple ID + 2FA).

```bash
npm install -g eas-cli
```

```bash
cd apps/mobile
eas login
```

```bash
eas build:configure --platform ios
```

That writes an EAS `projectId` into `app.json`. Then build on Expo's macOS workers:

```bash
eas build --platform ios --profile production
```

EAS will offer to create the Distribution Certificate and Provisioning Profile for you — say yes;
it needs your Apple ID and team. The build takes roughly 15–25 minutes. Then submit it:

```bash
eas submit --platform ios --latest
```

Apple processes the build (another 5–15 minutes), after which it appears in App Store Connect →
your app → TestFlight.

**The TestFlight link is generated by Apple, not by this repo.** In App Store Connect, open
TestFlight → your internal or external tester group → enable *Public Link*, and Apple gives you
the `testflight.apple.com/join/…` URL to share.

### First-build checklist

- Bundle identifier is `com.axune.mobile` (set in `app.json`); it must match the App Store
  Connect app record.
- `eas.json` uses `appVersionSource: "remote"`, so EAS owns the build number — no manual bumping.
- Version `0.1.0` is in `app.json`. Bump it for user-visible releases.
